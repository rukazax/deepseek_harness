# topic-bridge / Мост «тема Telegram → сессия DSH»

Входящая половина моста DSHarnes. Приём — в MCP telegram (`server.py`, telethon):
сообщение владельца в теме группы пишется в `/home/ka/.config/dsh-tg/inbox.jsonl`
и помечается прочитанным. Этот плагин забирает очередь и отдаёт текст в сессию
рабочего пространства как **обычный пользовательский промпт** — то же самое,
что набрать его в поле ввода в Web (`sessionController.prompt`, `mode: queue`).

- Тема → пространство: `workspaces[*].topic` в `dsharnes.json`; сессия — самая
  свежая живая (не архивная, не субагент) с `cwd` = путь пространства.
- Порядок: смещение в `inbox.offset`, доставка ровно один раз, недописанная
  строка ждёт следующего тика (2 с). Файл пересоздан — читаем с начала.
- Сбой доставки виден в теме (бот пространства пишет ⚠️) и в
  `topic-bridge.log`.
- Сообщения ботов (в том числе ответы DSH в темы) не считаются заданиями.

Почему приём в MCP telegram, а не отдельным процессом: второй коннект той же
MTProto-сессией Telegram отзывает как дубль авторизации, и тогда отваливаются
все `tg_*` инструменты разом.

Проверка: `npm test` (маппинг тема→пространство, выбор сессии, чтение очереди).
