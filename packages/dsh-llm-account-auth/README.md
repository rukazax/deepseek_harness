# dsh-llm-account-auth — вход в модели по подписке

Инструмент `llm_signin` для DeepSeek Harness: запускает, показывает и завершает OAuth-вход
в маршруты моделей, которые авторизуются **аккаунтом**, а не API-ключом.

## Зачем

`@deepseek-ai/dsh-llm-pi-ai` регистрирует по одному authorization-flow на каждый
установленный провайдер (`ctx.authorization.registerFlow`), но во всём продукте
`authorization.begin` вызывает только плагин аккаунта DeepSeek — со своей страницей
настроек. То есть подписочные маршруты (OpenAI ChatGPT Plus/Pro, Claude Pro/Max,
GitHub Copilot, xAI, OpenRouter) завести было нечем: ключа нет, а вход запустить некому.
Этот плагин закрывает ровно этот пробел — и ничего больше: он не трогает хранилище
секретов и не знает формата записи (grant пишет сам flow через `ctx.authorization`).

## Инструмент

| action | что делает |
|---|---|
| `list` | все зарегистрированные flow, их методы и признак «уже идёт» |
| `start` | начать попытку: `key` (например `openai-codex`), `method` (`oauth`), `wait` — секунды ожидания первой подсказки |
| `status` | подсказки, текущий вопрос и итог; `wait` — сколько ждать завершения |
| `submit` | ответ на вопрос flow (`text`): URL колбэка, код устройства, id опции |
| `cancel` | отменить попытку |

Попытка живёт в фоне: `start` сразу отдаёт ссылку (или код устройства), человек
завершает вход в браузере, `status` показывает, когда grant записан.

## Вход в OpenAI по подписке

```yaml
# profiles/<profile>/cordis.patch.yml
- id: llm-pi-ai
  name: "@deepseek-ai/dsh-llm-pi-ai"
  config:
    providers:
      openai-codex:
        displayName: OpenAI (ChatGPT subscription)
```

Дальше — `llm_signin action=start key=openai-codex method=oauth`. Flow спросит способ
входа (`browser` или `device_code`); `device_code` удобнее, если браузер не на той же
машине, что harness: колбэк на `127.0.0.1:1455` тогда недоступен.

Grant ложится в `$DSH_HOME/.credentials.yaml` записью `llm-pi-ai/openai-codex`
(`kind: grant`), её же читает адаптер при запросе. До входа `llm.listModels` для
маршрута возвращает пустой список, поэтому в селекторе моделей он не появляется —
и «битых» моделей в списке нет.

## Устройство

`mount.js` — точка монтирования: переимпортирует `impl.js` с уникальным query на каждый
mount. Загрузчик DSH импортирует модуль плагина один раз за процесс (обычный `import()`
без cache-busting), поэтому правка смонтированного файла иначе требует перезапуска;
с шимом достаточно `touch cordis.patch.yml`.

## Ограничения

- Плагин не рисует интерфейс: модель появляется в селекторе сама, как только grant есть.
- Ключи и пароли плагин не принимает; вопросы flow отдаются человеку как есть.
