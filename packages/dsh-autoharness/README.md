# dsh-autoharness

Самообслуживающийся слой навыков для DeepSeek Harness. Порт архитектуры
[tigerless-labs/autoharness](https://github.com/tigerless-labs/autoharness) (MIT)
на механизмы DSH: `session/event`, spawn-сабагент, `systemPrompt`, `tools.guard`
и обычные `SKILL.md`, которые подхватывает `dsh-skill-filesystem`.

Идея та же, что в оригинале: харнесс делает большую часть работы, но его слой
навыков каждый раз переписывают руками. Здесь этот слой поддерживает себя сам —
учится на реальных сессиях, сливает дубли, обновляется в работе и убирает то,
чем перестали пользоваться.

## Что происходит на практике

1. Плагин слушает `session/event` и складывает в свой файл редакченное окно
   сессии (`user/message`, `assistant/message`, `tool/result`), обрезая записи
   и общий объём.
2. Считает **tool-call'ы**, а не ходы: разговор без инструментов не запускает
   обучение. Каждые `reflectEveryN` вызовов в конце хода окно снимается в
   `runs/<run-id>.window.jsonl`.
3. Запускается **рефлектор** — обычный сабагент через `subagents.startActivation`
   с `delivery: 'caller'`. Он не имеет права писать: `tools.guard` запрещает
   ему `write`/`edit`/`bash`/`pwsh`, а единственный доступный инструмент —
   `autoharness_stage_skill`, который кладёт **предложение** в очередь.
4. **Promoter** (детерминированный код плагина) разбирает очередь: валидирует
   имя, префикс, описание, тело, причину, возможность patch, «своё/чужое»,
   и только после этого атомарным `rename` кладёт `SKILL.md`. Каждый прогон
   оставляет отчёт: что легло, что отклонено и почему.
5. При старте сессии в промпт добавляется **индекс** собственных навыков
   (сгруппированный по слоям, с счётчиками использования) и строка о последнем
   прогоне, включая отклонённые предложения.
6. **Жизненный цикл** считается при старте сессии: новорождённый навык сидит
   на испытательном сроке, зрелый без единого `use` и `view` уходит в
   `.archive/`, а при переполнении пула вытесняется самый низкий по
   `use / запросы`. Удаления нет — только перенос, откуда можно вернуть.

## Карта компонентов

| Оригинал | Здесь |
|---|---|
| CAP · hooks `PreToolUse`/`Stop` | `session/event` + `turn/end` |
| REF · `claude --agent reflector` | `ctx.subagents.startActivation({ provider: 'spawn', delivery: 'caller' })` |
| `stage_skill` MCP | инструмент `autoharness_stage_skill` |
| promoter | `promoteIntent()` в `index.js`, атомарная запись |
| IDX · `SessionStart` additionalContext | `ctx.systemPrompt.context('autoharness:index')` |
| MNG · `lifecycle.evaluate` | `lifecycle()` — та же формула: probation → graduation → capacity |
| curator | тот же рефлектор с режимом `curator` каждые `consolidateEveryN` |
| LED | `.ledger.jsonl` + `references/evidence-<hash>.md` |
| `AUTOHARNESS_*` env | поля `config` в `cordis.patch.yml` |

## Установка

```bash
# каталог бандла — этот репозиторий/папка
dsh plugin add /path/to/dsh-autoharness
```

Или через инструмент `plugin_manager` с действием `install_bundle` и абсолютным
путём к каталогу. Конфиг правится в `cordis.patch.yml` профиля, строка `autoharness`.

Навыки пишутся в `<DSH_HOME>/skills` (слой `global`) или `<project>/.dsh/skills`
(слой `project`) — оба корня уже сканирует `dsh-skill-filesystem` и следит за ними,
так что новый `SKILL.md` появляется в каталоге без перезапуска.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `autoharness_learn` | не ждать каденцию: снять окно и запустить рефлексию сейчас |
| `autoharness_stage_skill` | очередь предложений (вызывает только рефлектор) |
| `autoharness_status` | счётчики запросов, навыки с `use`/`view`, очередь, последний прогон |

## Конфиг

| Поле | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `true` | выключить слой целиком |
| `reflectEveryN` | `50` | tool-call'ов до рефлексии |
| `consolidateEveryN` | `250` | запросов до прохода куратора (0 — выкл.) |
| `maturityGlobal` / `maturityProject` | `300` / `100` | запросов, после которых навык выходит из испытательного срока |
| `capacityGlobal` / `capacityProject` | `20` / `50` | потолок зрелых навыков |
| `skillPrefix` | `ah-` | обязательный префикс новых имён |
| `layer` | `global` | слой по умолчанию для новых навыков |
| `provider` | `spawn` | провайдер сабагента для рефлектора |
| `indexSuspended` | `false` | не вставлять индекс в промпт (метрики продолжают считаться) |
| `indexMaxBytes` | `1800` | бюджет индекса |
| `captureMaxRecordBytes` | `4000` | обрезка одной записи окна |
| `captureMaxWindowBytes` | `200000` | обрезка окна |
| `maxBodyLines` | `60` | максимум непустых строк в теле навыка |
| `stateDir` | `null` | свой каталог состояния (по умолчанию `<DSH_HOME>/autoharness`) |
| `graderOnly` | `false` | только захват и метрики, без рефлексии (для тестов) |

## Состояние

```
<stateDir>/
  capture/<session>.jsonl        окно текущей сессии
  runs/<run-id>.window.jsonl     снимок окна, который читает рефлектор
  runs/<run-id>.json             отчёт: landed / rejected
  intents/<run-id>/*.json        очередь предложений
  intents/interactive/           предложения из основной сессии
  requests/<layer>-<hash>.json   знаменатель adherence
  sessions/counters.json         счётчики tool-call'ов (снимок)
  children.json                  сессии-дети (recursion guard)
  last_run.json                  строка для индекса
  ledger.jsonl                   журнал архивации
```

## Безопасность и границы

- Рефлектор физически не может писать: guard режет `write`, `edit`,
  `apply_patch`, `bash`, `pwsh` для сессий, которые породил плагин.
- Promoter трогает **только** навыки со своим маркером `.autoharness.json`;
  чужие и написанные руками не читаются и не архивируются.
- Окно и evidence проходят редакцию секретов на выходе из захвата и повторно
  при записи evidence.
- Пути подфайлов проверяются на выход из каталога навыка.
- При отсутствии `dsh-subagent` плагин не падает: захват, метрики и индекс
  работают, рефлексия пишет предупреждение в лог.

## Отличия от оригинала

- Нет Python и внешних зависимостей: один ESM-файл.
- Окно сессии строится из событий DSH, а не из файла транскрипта (сессии DSH
  лежат в zstd-JSONL).
- Куратор — тот же рефлектор в режиме `curator`, а не отдельный агент.
- Навыки — нативные `SKILL.md` DSH, поэтому «use» считается по вызову
  инструмента `skill`, а «view» — по чтению файлов навыка.

## Что выяснилось на живых сессиях

Четыре дефекта, найденные первым же боевым прогоном (все исправлены, все
покрыты `test/smoke.mjs`):

- **Рефлектор получал запрещённый `bash` и сдавался.** Промпт говорил «прочитай
  файл», guard режет shell — рефлектор не знал про `read` и возвращал «0 landed».
  Теперь промпт прямо называет `read`/`grep`/`glob` и говорит, что shell запрещён.
- **`agent/created` не срабатывает для сессий, живших до монтирования.** После
  ремаунта/обновления плагина прогон молча пропускался («no live agent»). Агент
  теперь разрешается лениво через реестр `agents`.
- **Счётчик tool-call'ов не переживал ремаунт:** `counters.json` писался, но
  никогда не читался, поэтому триггер каждый раз начинал с нуля.
- **`autoharness_stage_skill` возвращал недекларированный ключ `file`** и падал
  на валидации выходной схемы — то есть не мог застеджить ни одного интента.

Плюс: интент, застедженный перед ремаунтом, раньше терялся в очереди навсегда.
Теперь окно прогона на диске само по себе доказывает существование прогона, а
очередь разгребается на каждом `turn/end`, а не только `interactive`.
