# Changelog

## 2026-11-09 — mcp-github-universal: универсальный доступ к GitHub по MCP

RU: новый пакет `mcp-github-universal` — один бандл подключает к DSH два MCP-сервера и делает GitHub доступным «под ключ». Облачная часть — официальный удалённый GitHub MCP Server (`api.githubcopilot.com/mcp/x/all`, все toolsets; `Authorization` собирается из `GITHUB_PERSONAL_ACCESS_TOKEN` через `!!js`, токен в пакете не хранится); локальная — `mcp-server-git` в venv `~/.dsh/venvs/mcp-git` (python-путь разрешается через `dshHomePath`). Поведение деликатное: `failOnStartupError` — false для github-части (без токена DSH стартует, инструменты появятся позже), true для git-сервера; reconnect 0,5 с → 30 с, до 10 попыток; таймаут вызовов — 120 с. Проверено: `mcp__github__get_me` возвращает аккаунт владельца токена, инструменты `mcp__git__*` регистрируются и отвечают. Двуязычный README пакета, страницы `docs/ru` и `docs/en`, схемы `assets/mcp-github-universal-architecture-{ru,en}.svg`, строка в таблицах корневого README и ветки в обеих Mermaid-схемах. По пути задокументировали ловшку fine-grained PAT: запись в репозиторий открывается только через *Repository permissions → Contents → Read and write* (правку сохраняем кнопкой *Update token*, строку токена перевыпускать не нужно). Попутно глобальное правило публикации расширено: теперь оно покрывает настройки и правила — включая созданные ранее, которые дополняются в репозитории (backfill).

EN: new `mcp-github-universal` package — one bundle wires two MCP servers to DSH and makes GitHub available out of the box. The cloud part is the official remote GitHub MCP Server (`api.githubcopilot.com/mcp/x/all`, all toolsets; the `Authorization` header is assembled from `GITHUB_PERSONAL_ACCESS_TOKEN` via `!!js`, the token never sits in the package); the local part is `mcp-server-git` in the `~/.dsh/venvs/mcp-git` venv (the python path resolves through `dshHomePath`). Behaviour stays polite: `failOnStartupError` — false on the GitHub part (without a token DSH still boots and the tools appear later), true on the git server; reconnect 0.5 s → 30 s, up to 10 attempts; tool-call timeout 120 s. Verified: `mcp__github__get_me` returns the token owner's account, the `mcp__git__*` tools register and answer. Bilingual package README, `docs/ru` and `docs/en` pages, diagrams `assets/mcp-github-universal-architecture-{ru,en}.svg`, rows in the root README tables and new branches in both Mermaid charts. Along the way we documented the fine-grained PAT pitfall: repository write access only opens via *Repository permissions → Contents → Read and write* (persisted with the *Update token* button; re-issuing the token string is unnecessary). The global publishing rule is extended accordingly: it now covers settings and rules — including previously created ones, which are backfilled into the repository.

## 2026-10-30 — claude-bridge: проверка после перезагрузки

RU: `claude-bridge` получил автопроверку `tools/post-restart-check.ps1` и флаг `install.ps1 -WithCheck`. После входа в систему (через 2 и 10 минут) задача проверяет процесс DSH, `/health` моста, состояние задачи «Claude Bridge», маршрут в профиле, разбор YAML через `js-yaml` и делает настоящий запрос через мост. Отчёт пишется в `%USERPROFILE%\.dsh\reports\`, итог виден в `LastTaskResult`, при наличии `CLAUDE_BRIDGE_CHAT_ID` и токена приходит уведомление в Telegram. Попутно исправлено: установщик больше не путает путь профиля с флагом `-ProfilePatch` (в PowerShell регистр не различается), тело тестового запроса отправляется в UTF-8 — иначе кириллица превращалась в «?».

EN: `claude-bridge` gained `tools/post-restart-check.ps1` and the `install.ps1 -WithCheck` flag. After logon (2 and 10 minutes later) the task verifies the DSH process, bridge `/health`, the `Claude Bridge` task state, the route in the profile, YAML parsing through `js-yaml`, and sends a real prompt through the bridge. Reports go to `%USERPROFILE%\.dsh\reports\`, the verdict is surfaced in `LastTaskResult`, and a Telegram note is sent when `CLAUDE_BRIDGE_CHAT_ID` and the token exist. Also fixed: the installer no longer collides the profile path with the `-ProfilePatch` switch (PowerShell is case-insensitive), and the probe body is sent as UTF-8 — Cyrillic used to arrive as question marks.

## 2026-10-30 — claude-bridge

RU: новый пакет `claude-bridge` — подписка Claude Pro/Max внутри DSH. Локальный эндпоинт в формате Anthropic Messages (`/v1/messages`, обычный ответ и SSE, `/v1/models`, `/health`) выполняет запросы через `claude` CLI, у которого уже есть OAuth подписки. Маршрут регистрируется в `llm-pi-ai` (`api: anthropic-messages`, `baseURL: http://127.0.0.1:8790`), установщик `install.ps1` ставит задачу автозапуска, ждёт `/health` и патчит профиль с резервной копией. Ограничения честно описаны: инструменты DSH через мост недоступны, счётчик токенов нулевой. Двуязычный README, страницы `docs/ru` и `docs/en`, схема `assets/claude-bridge-architecture-{ru,en}.svg`.

EN: new `claude-bridge` package — a Claude Pro/Max subscription inside DSH. A loopback Anthropic Messages endpoint (`/v1/messages` with plain and SSE replies, `/v1/models`, `/health`) executes requests through the `claude` CLI that already holds the subscription OAuth. The route is registered in `llm-pi-ai` (`api: anthropic-messages`, `baseURL: http://127.0.0.1:8790`); `install.ps1` registers the autostart task, waits for `/health` and patches the profile with a backup. Limitations are stated plainly: DSH tools are unavailable through the bridge and token counters read zero. Bilingual README, `docs/ru` and `docs/en` pages, diagram `assets/claude-bridge-architecture-{ru,en}.svg`.
