IME-составление и repeat перехват не трогают; меню команд (/) сохраняет свой arbitration. Двуязычный README пакета, docs-страницы, строка в таблицах корневого README.

EN: new `dsh-composer-alt-enter` micro-package — in the chat composer Alt+Enter inserts a line break, plain Enter keeps submitting, Shift+Enter also breaks the line (built-in). DSH deliberately leaves Alt+Enter to application shortcuts; the owner-less key is now claimed: keydown capture phase, target — the active Lexical editor, insertion through the official `inputActions.insertText` (undoable) with an `execCommand('insertLineBreak')` fallback; the event is swallowed before Lexical reacts — no double breaks, no accidental sends. IME composition and key repeat stay untouched; the command menu ( / ) keeps its arbitration. Bilingual package README, docs pages, a row in the root README tables.

## 2026-11-09 — dsh-memory-hub: общий контекст всех чатов и workspace

RU: новый пакет `dsh-memory-hub` — общая память всех чатов и workspace внутри профиля DSH. Каждый ход всех сессий автоматически попадает в SQLite-хранилище (`~/.dsh/memory/ctxdb.sqlite`, WAL: запросы, ответы, пары задача+решение); recall — гибрид косинуса hashed-TF-IDF (4096-d) и лексического покрытия с бонусом своего workspace и затуханием свежести; подстановка в контекст — урезанный runtime-контекст (≤900 символов) и только при попадании — иначе ноль токенов. Повторяющиеся формулировки (2+ раза) минируются в авто-рутины с последним решением и подставляются блоком `<routine>`; fuzzy-матчер — слово/префикс≥5/корень≥4. Добавлены профиль стиля автора (tool `memory_style`), недельный причинно-следственный анализ (графа зависимостей, мосты workspace, решения против результатов, цели и незавершённые ходы, рекомендации → Obsidian `Аналитика/` и `memory_analyze`), Obsidian-синхронизация (Facts/Tasks/Routines пишутся автоматически, заметки с `memory-hub: fact` индексируются обратно) и интерфейс для человека: информер под композером и вкладка-дашборд `🧠 Память` в правой боковой панели (чанки, рутины, подстановки, экономия токенов, кнопки запуска). Инструменты: `memory_search`, `memory_save`, `memory_routines` (approve/forget по подтверждению), `memory_analyze`, `memory_style`. Двуязычный README пакета, страницы `docs/ru`/`docs/en`, схемы `assets/dsh-memory-hub-architecture-{ru,en}.svg`, строки и Mermaid-ветки в корневом README. Хранилище и vault — вне ядра dsh и переживают обновления.

EN: new `dsh-memory-hub` package — shared memory of all chats and workspaces inside the DSH profile. Every turn of every session lands in an SQLite store (`~/.dsh/memory/ctxdb.sqlite`, WAL: requests, answers, task+solution pairs); recall is a hybrid of hashed-TF-IDF cosine (4096-d) and lexical coverage with an own-workspace bonus and freshness decay; the injection is a capped runtime context (≤900 chars) only on a hit — otherwise zero tokens. Repeated phrasings (2+ times) are mined into auto-routines carrying the last solution and served as a `<routine>` block; the fuzzy matcher is word/prefix≥5/root≥4. Added the author's style profile (`memory_style`), the weekly causal analysis (dependency graph, workspace bridges, decisions vs results, goals and unfinished turns, recommendations → Obsidian `Аналитика/` and `memory_analyze`), Obsidian sync (Facts/Tasks/Routines written automatically; notes with `memory-hub: fact` are indexed back) and a human-facing UI: an informer under the composer and a `🧠 Memory` dashboard tab in the right sidebar (chunks, routines, injections, token savings, run buttons). Tools: `memory_search`, `memory_save`, `memory_routines` (approve/forget on user confirmation), `memory_analyze`, `memory_style`. Bilingual package README, `docs/ru`/`docs/en` pages, diagrams `assets/dsh-memory-hub-architecture-{ru,en}.svg`, rows and Mermaid branches in the root README. Storage and vault live outside the dsh core and survive updates.

## 2026-10-30 — dsh-sync: синхронизация истории сессий

RU: новый пакет `dsh-sync` — двусторонняя синхронизация истории сессий DSH между Windows-установкой и Linux-инстансом. Переносятся логи сессий и вложения; вызовов моделей нет, токены не тратятся. Ключевая часть — `convert.js`: DSH требует абсолютный `cwd` для своей платформы, поэтому конвертер правит только строку заголовка через карту путей и перепаковывает zstd (первый кадр — заголовок, дальше события без изменений). Оркестратор `sync-dsh-sessions.ps1` считает sha256 обеих сторон, выбирает push/pull, разрешает конфликты по времени с бэкапом, ведёт `state.json` и `sync.log`. Скрипты параметризованы: домашний каталог берётся из `USERPROFILE`, SSH-алиас — из `DSH_SYNC_SSH` (по умолчанию `debian17-root`). Двуязычный README, страницы `docs/ru/dsh-sync.md` и `docs/en/dsh-sync.md`, схемы `assets/dsh-sync-architecture-{ru,en}.svg`, запись в таблице README. Проверено: `node --check`, паритет конвертера с рабочей копией, `-DryRun` проходит.

EN: new `dsh-sync` package — two-way sync of DSH session history between a Windows install and a Linux instance. Session logs and attachments are transferred; no model calls, so no tokens are spent. The core is `convert.js`: DSH requires an absolute `cwd` for its own platform, so the converter rewrites only the header line through a path map and re-frames zstd (first frame is the header, then untouched events). The `sync-dsh-sessions.ps1` orchestrator hashes both sides with sha256, chooses push/pull, resolves conflicts by modification time with backups, and maintains `state.json` and `sync.log`. Scripts are parameterised: the home directory comes from `USERPROFILE`, the SSH alias from `DSH_SYNC_SSH` (default `debian17-root`). Bilingual README, pages `docs/ru/dsh-sync.md` and `docs/en/dsh-sync.md`, diagrams `assets/dsh-sync-architecture-{ru,en}.svg`, a row in the README table. Verified: `node --check`, converter parity with the working copy, `-DryRun` passes.
