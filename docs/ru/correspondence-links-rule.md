# Глобальное правило: учитывать ссылки для скачивания из переписок проекта · Global correspondence-links rule

**RU** · [English](../en/correspondence-links-rule.md)

## RU

### Формулировка

> **При изучении и анализе материалов по проекту обязательно учитывать информацию, которую
> предоставляют ссылки для скачивания из переписок в рамках изучаемого проекта и периода.**

Правило действует в каждой сессии DSH, во всех профилях и рабочих каталогах (локальная копия —
`~/.dsh/AGENTS.md`).

### Конкретно

1. **Ссылки — часть исходных данных.** В переписке (почта, мессенджеры, протоколы) ссылки на скачивание
   файлов (`disk.yandex.ru`, `disk.360.yandex.ru`, `sarex.*`, Dropbox/Google Drive и аналоги) считаются
   полноправными исходными материалами проекта наравне с вложениями писем и локальными папками. Нельзя
   считать изучение проекта завершённым, пока такие ссылки не собраны и не отработаны.

2. **Собирать в границах проекта и периода.** Собираются ссылки из писем/сообщений, относящихся к
   изучаемому проекту и к изучаемому периоду (тема, участники, контекст). Ссылки из посторонних тем
   игнорируются; при сомнении — уточнить у пользователя.

3. **Отработать каждую ссылку.** По каждой ссылке: скачать/открыть содержимое, изучить файлы, зафиксировать
   их названия, даты и версию; сделать выводы с учётом этих материалов. Если ссылка битая, требует доступа
   или содержимое не совпадает с описанием в письме — явно зафиксировать это в результатах анализа,
   не пропуская молча.

4. **Сверять с локальными копиями и версиями.** Материалы по ссылкам сверять с уже собранными локальными
   копиями (одинаковый файл по дате/версии — брать свежую; разные версии — зафиксировать обе и их
   расхождения). Отражать в отчётах: какие материалы взяты по ссылкам, с какой даты/версии.

5. **Хранить след.** Скачанные по ссылкам материалы сохранять в рабочем каталоге с пометкой источника
   (письмо/дата/ссылка), чтобы анализ был воспроизводим; в отчётах указывать ссылку и письмо-источник.

### Пример применения

В проекте «Символ 36,39,40» при разборе почтового ящика `amn.control.info@yandex.ru` ссылки из писем
(`disk.yandex.ru/d/…`, `sarex.dsinv.ru/documentations/…`) обрабатываются наравне с вложениями: реестры
MAF, графики выдачи РД, ТЗ на двери и другие материалы, переданные по ссылкам, скачиваются, версионируются
и учитываются в отчётах с указанием письма-источника.

## English

### Statement

> **When studying and analysing project materials, always take into account the information provided
> by download links found in the correspondence of the project and period being studied.**

The rule applies in every DSH session, in all profiles and working directories (local copy —
`~/.dsh/AGENTS.md`).

### Details

1. **Links are part of the source data.** In correspondence (e-mail, messengers, protocols) links to
   file downloads (`disk.yandex.ru`, `disk.360.yandex.ru`, `sarex.*`, Dropbox/Google Drive and alike)
   count as first-class source materials on a par with e-mail attachments and local folders. Studying
   a project is not complete until such links have been collected and processed.

2. **Collect within the project and period.** Collect links from messages belonging to the project and
   the period being studied (subject, participants, context). Links from unrelated threads are ignored;
   when in doubt, ask the user.

3. **Process every link.** For each link: download/open the content, review the files, record their
   names, dates and versions; draw conclusions with these materials taken into account. If a link is
   broken, requires access, or its content does not match the message description — record this
   explicitly in the analysis results instead of skipping it silently.

4. **Reconcile with local copies and versions.** Reconcile link-based materials with already collected
   local copies (same file by date/version — take the freshest; different versions — record both and
   their differences). In reports, state which materials were taken via links and from which date/version.

5. **Keep the trace.** Store downloaded materials in the working directory with a source note
   (message/date/link) so the analysis is reproducible; in reports, reference the link and the source message.

### Example

In the «Символ 36,39,40» project, while processing the `amn.control.info@yandex.ru` mailbox, links in
messages (`disk.yandex.ru/d/…`, `sarex.dsinv.ru/documentations/…`) are processed on a par with
attachments: MAF registries, RD delivery schedules, door specifications and other materials shared via
links are downloaded, versioned and taken into account in reports with the source message referenced.
